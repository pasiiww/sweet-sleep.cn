# 历史咨询 RAG 召回测评

`rag_cases.json` 从 2026 年 9 月的 QQ 咨询和已核实知识中人工改写了 29 个问题：26 个有明确证据，3 个应避免套用相似商品的知识。文件不含聊天原文、群成员标识、订单或私密链接。`rag_fixture.json` 保存当日 49 条生效 QA 的问题标题和 5 份文档的脱敏摘要；答案是占位文本，只测试召回和排序。

在项目根目录运行：

```bash
python3 services/knowledge/evals/eval_rag.py
python3 services/knowledge/evals/eval_rag.py --db /path/to/snapshot/knowledge.db
```

第二种方式针对本地 SQLite 快照测评真实知识库，不调用模型、不修改线上数据。正例要求所有指定证据进入前 5 条，并统计至少一条证据排第一的次数；反例统计指定错误商品的 QA 是否进入前 5 条。测评不会证明模型最终回答正确，仍需人工核对涉及库存、日期和跨商品的回答。

2026-09-24 的线上数据库快照对比：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 正例全部证据进入前 5 条 | 22 / 26 | 26 / 26 |
| 正例第一条即正确证据 | 1 / 26 | 26 / 26 |
| 反例混入指定错误 QA | 3 / 3 | 0 / 3 |

后续更新知识库时，应重新检查问题和标准证据。测评脚本会在证据缺失时显示 `null` 排名，不会把未命中的案例算作通过。
